### Work done
**`fix/psd-export-ids`** (1 commit, 0c20e7f6, on main dbca08cd), file `crates/io/src/psd_export.rs`
- **Text slots (review finding R1).** Every type layer has a `TextIndex`, its slot in the document's `Txt2` block. Export handed these numbers out in one pass. A text layer made in PhotoCraft that came earlier in the layer order than an imported Photoshop text layer took slot 0. The imported layer was then renumbered, and its Photoshop-written `Txt2` object was rebuilt from scratch, losing glyph positions and the automatic kerning mode. Now every kept number is reserved first, then the new layers are numbered (the same two passes the layer ids already used).
  - Why it matters: this is the everyday thumbnail workflow, opening a template and adding a new text layer. Wishlist item 1, and the Photoshop-compatibility thread of #2469 / #2717.
- **Layer-id overflow (review finding R3).** Group dividers got ids counting up from the highest kept `lyid`. If a file kept `0xFFFFFFFF`, a debug build panicked with an overflow, and a release build wrapped around to duplicate ids. `fresh_id` now wraps, skips 0, and skips ids already in use.
- **Tests:** new `crates/io/tests/psd_export_ids.rs`. Both tests fail on main (the second with the overflow panic at `psd_export.rs:368`) and pass with the fix.
